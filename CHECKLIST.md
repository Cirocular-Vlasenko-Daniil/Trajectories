# Trajectories — ревизия

Рабочий документ для прохода по каждому модулю: что он умеет сейчас, как
живёт в цепочке с другими, и какие решения по нему ещё не приняты.

Отмечай `[x]` то, что проверил на железе. Решения записывай прямо в
строку «Решение:» — потом по ним пройдёмся кодом.

Состояние на 21.10.2026, `trajectories.cpp` ~4400 строк, 20 модулей + EMPTY.
Тесты: `test/run.sh` (см. test/README.md).

---

## Как читать

Каждый модуль описан по одной схеме:

- **Параметры** — главная страница · подстраница
- **В шину** — что и когда кладёт в `busCur`, то есть что увидят те, кто
  армлен на него
- **Из шины** — что берёт и что игнорирует
- **Открыто** — то, по чему нужно решение

Три вещи, которые стоит держать в голове на всём проходе:

1. **Шина несёт до 4 нот, у каждой своя velocity, плюс лад и тоника.**
   Всё, что модуль не положил в шину, для следующего звена не
   существует. Дублей в аккорде не бывает — `dedupeChord`.
2. **Читается снимок с начала цикла.** Кольца не виснут, а работают как
   обратная связь с задержкой в цикл.
3. **`SlotCfg` = 124 байта и он в патчах.** Любое новое поле обнуляет
   все восемь сохранений.

## 0. Общие механизмы

Их стоит пройти первыми: решения здесь меняют смысл половины таблиц ниже.

### 0.1 Лад внешнего входа

- [ ] `extSignal.scale` и `extSignal.root` **не выставляются никогда** —
      проверено, ни одного присваивания в коде.

Всё, что приходит с клавиатуры, для цепочки звучит в **до мажоре**. Это
значит, что GLIDER скользит по чужому ладу, ADD строит терцию не от того
корня, MATH считает ступени неправильно, SHIFT в режиме WALK уводит ноты
из твоего лада в C major.

Варианты:
- взять лад у первого генератора в цепочке (как LOGIC берёт сетку);
- отдельные `SCALE`/`ROOT` на странице настроек для EXT;
- определять лад по входящим нотам (дорого и ненадёжно);
- оставить хроматику (`scale = CHRM`) — честнее нынешнего мажора и
  бесплатно.

**Решение:** лад берётся у первого генератора на устройстве; если
генератора нет вовсе — хроматика. **Сделано.**

### 0.2 Кто вообще доходит до шины

Проверено по коду:

| Как публикует | Модули |
|---|---|
| в `onCapture`, сразу | ADD · KEYTRACK · MATH · SHIFT · MULTI OUT · POLY SPLIT · ROUND ROBIN · ENVELOPE · MORPH LFO |
| в `serviceProcessor`, по сетке | DUST · LOGIC |
| через планировщик (`pub`), в момент, когда нота звучит | STRUM · NOTE DELAY · GLIDER |
| со своего шага | ARPEGGIO |
| **никогда** | **META** |

- [ ] META не публикует ничего. Это осознанно (он модулирует, а не
      обрабатывает) — но слот, армленный на META, получает пустоту
      молча, без всякого признака на экране.

**Решение:** META прозрачен — армленный на него слот берёт то, что
читает сам META. Цепочка из META проходится насквозь, кольцо даёт
пустоту. **Сделано.**

### 0.3 Velocity

- [ ] Едет по шине у каждой ноты своя. Модули её **пропускают**, а не
      подменяют.
- [ ] Меняют velocity намеренно: STRUM (акцент щипка), NOTE DELAY
      (затухание эха), ADD (своя `VEL` у добавленной ноты), SHIFT
      (`VEL` за круг), TOPOLOGY (акцент из карты).
- [ ] Генераторы, кроме TOPOLOGY, шлют `DEFAULT_VEL` — плоско.

**Открыто:** нужна ли velocity как источник для META (сейчас источников
три) и как четвёртый режим сравнения LOGIC. Обсуждали, не делали.

**Решение:** оставляем как есть.

### 0.6 Полифония по цепочке

- [x] Два голоса шага, схлопнувшиеся после квантования на одну высоту,
      разводятся на ступень: три выставленные ноты дают три звучащие.
      Было — в 9 ладах из 10 слышно две вместо трёх.
- [x] `publish` не пропускает дубли на шину, `fireGenerator` — в MIDI.
- [x] ADD пропускает входной аккорд целиком, а не `capNotes[0]`.
- [x] NOTE DELAY повторяет аккорд, а не нижнюю ноту.
- [ ] Моно по устройству: SHIFT, GLIDER, DUST, KEYTRACK, LOGIC, MATH.
      Проверить на слух, что это не мешает.
- [ ] ROUND ROBIN в режиме CYCLE на аккорде берёт одну ноту за событие
      и теряет остальные. Решить: так и надо или раскладывать аккорд.

### 0.8 Модуляция: слот как источник

- [x] Колонку ведёт СЛОТ, а не номер CC. Номер был деталью протокола:
      приходилось держать магическую цифру в голове и сверять её на
      двух страницах.
- [x] Что слот подаёт, решает он сам: у шести возможных источников это
      их единственный непрерывный выход, уже лежащий в `ccValue` шины.
      Остальные при листании пропускаются.
- [x] Отсчёт контекстный: LFO, KEYTRACK, NOTE DELAY — двусторонний,
      ENVELOPE, DUST, MATH, EXT — от нуля.
- [x] Глубина в единице параметра: до восьми значений — позиции, дальше
      проценты. Переключатель из двух значений перестал быть особым
      случаем. До этого у 23 колонок из 160 была мертва треть ручки.
- [x] EXT: номер контроллера выводится из слота и колонки
      (`20 + слот·8 + колонка`), прибор показывает его сам.
- [x] META удалена. Вместе с ней ушли адресация по номеру параметра,
      `metaDepth[3]`, `metaLo/Hi/Val`, `metaSeen`, `metaRawPrev`,
      `metaLastMs` и все обращения к `float` на чипе без FPU.
- [ ] **Потеря:** вторые строки колонок (тоника, BPM, `Y` карты,
      номера CC у KEYTRACK, `ROT` у SHIFT) вести больше нечем — слой
      покрывает только видимые колонки. Индексы `modOffset` выше 7
      всегда нули; таблицу не сжимал, чтобы вернуть было одной правкой.
- [ ] Проверить на железе жест и то, достаточно ли рамок на карте,
      чтобы видеть, что вообще ведётся.

## 6. Связки, которые стоит прогнать живьём

Не по модулю, а по цепочке — здесь вылезает то, чего не видно поодиночке.

- [ ] `GEN → DUST → RROBIN` — облако раскладывается по голосам
- [ ] `GEN(аккорд на шаге) → ARP → NDELAY` — аккорд, арпеджио, эхо
- [ ] `GEN → STRUM → RROBIN` — щипок по голосам, проверить `pub`
